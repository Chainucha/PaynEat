# Ticket: สแกนบาร์โค้ดและฉลากตาชั่ง

**Priority:** 🟠 High
**สถานะ (2026-09-27):** ✅ เสร็จแล้ว (`docs/DECISIONS.md` #49)
**Ref:** `docs/FEATURE-GAP-ANALYSIS.md` — หมายเหตุการอัปเดต #48–#51 (ร้านเนื้อ/ขายส่ง)

## ปัญหา
ไม่มีช่องทางสแกนเลย พนักงานต้องไล่หาเมนูบนจอทุกครั้ง ร้านเนื้อที่ใช้ตาชั่งพิมพ์ฉลาก (ชั่งแล้วแปะสติกเกอร์
บาร์โค้ดที่มีน้ำหนักอยู่ในรหัส) ต้องพิมพ์น้ำหนักซ้ำเองจากฉลาก — ช้าและพิมพ์ผิดได้

## ขอบเขตงาน
- **บาร์โค้ดสินค้า** `menu_items.barcode` (ตัวเลข/อังกฤษ/ขีด ≤ 32 ตัว) — สแกนแล้วลงตะกร้า 1 ชิ้น
  (ถ้าเป็นเมนูขายตามน้ำหนักที่ไม่มีน้ำหนักในรหัส → เปิดกล่องชั่งให้กรอก)
- **ฉลากตาชั่ง EAN-13** = prefix + PLU + น้ำหนัก (กรัม) + check digit — ร้านตั้ง prefix (ขึ้นต้นด้วย 2,
  1–3 หลัก) และจำนวนหลัก PLU (4–6) ให้ตรงกับตาชั่งของตัวเองที่หน้าตั้งค่า ต้องเหลือหลักน้ำหนัก 4–6
  หลักเสมอ (ค่าเริ่มต้น `20` + PLU 5 หลัก + 5 หลักกรัม) `menu_items.scale_plu` เก็บแบบตัด 0 นำหน้า
- **ความถูกต้อง**: check digit ผิด = ไม่เดาน้ำหนัก แจ้งให้สแกน/ชั่งใหม่, รหัสซ้ำกับเมนูอื่นในสาขาเดียวกัน
  ไม่ได้ (409), PLU ใช้ได้เฉพาะเมนูขายตามน้ำหนัก, บาร์โค้ดที่ลงทะเบียนไว้ตรงตัวชนะการอ่านเป็นฉลาก
- **อ่านรหัสในเครื่อง** (`BarcodeResolver` ฟังก์ชันบริสุทธิ์) ไม่ถาม backend — ดู `docs/DECISIONS.md` #49
- **แอป**: ช่อง "สแกนบาร์โค้ด / ฉลากตาชั่ง" บนหน้ารับออเดอร์ (focus ให้อัตโนมัติบนจอกว้าง รองรับ
  เครื่องสแกน USB/บลูทูธที่ทำตัวเป็นคีย์บอร์ด), ช่องบาร์โค้ด/PLU ในฟอร์มเมนู, ค้นหาเมนูด้วยบาร์โค้ด,
  ส่วน "ฉลากตาชั่ง" ในหน้าตั้งค่าพร้อมตัวอย่างรูปแบบ
- **Demo Mode**: บาร์โค้ด EAN-13 จริง 2 ตัว (`8850999320014`, `8850999320021`) + PLU 101–103

## ขอบเขตที่ตั้งใจไม่ทำ
- ~~สแกนด้วยกล้องมือถือ~~ → ทำแล้วใน ticket 22 (`22-live-scale-camera-scan.md`) รหัสจากกล้องเข้า
  `BarcodeResolver` ตัวเดียวกับเครื่องสแกนแบบคีย์บอร์ด

  ระบบคิดราคาจากน้ำหนักเสมอ
