## ปัญหา
เชนร้านที่ใช้ PaynEat ERP ต้องให้รายการวัตถุดิบ สาขา (และต่อไปคือเมนู ราคา สูตร) มีเจ้าของที่เดียวคือ ERP แต่ POS ทุกวันนี้
จัดการข้อมูลพวกนี้เองทั้งหมด ถ้าปล่อยให้แก้ได้ทั้งสองที่ ข้อมูลจะไม่ตรงกันภายในสัปดาห์เดียว

## ทำไมสำคัญ
เป็นขั้นแรกที่ทำให้ POS เข้าร่วมระบบนิเวศได้ **โดยไม่ทำให้ร้านเดี่ยวที่โหลด POS ไปใช้เสียอะไรเลย**

## ขอบเขตงาน
- **ค่าเริ่มต้นคือโหมดใช้งานเดี่ยว** ทำงานเหมือนเดิมทุกประการ ไม่มีอะไรเปลี่ยนสำหรับร้านที่ไม่มี ERP
- **เข้าโหมดเชื่อมต่อ**: admin ใส่ URL ของ ERP และ machine credential (`pnepos_…`) ที่ได้ตอนลงทะเบียน POS instance ใน ERP
  - ตอนบันทึกให้เรียก `GET /api/v1/pos/instance` ตามสัญญา POS v1 **1.0.0** (PaynEat-ERP#55, merge แล้ว) เพื่อยืนยัน credential และรับรหัส
    instance, `contractVersion` และสาขาที่ ERP ให้ instance นี้ดูแล — สาขาใน POS ที่ไม่อยู่ในรายการ ให้บอกชัดบนหน้าจอ
  - ถ้า `contractVersion` เป็น major ที่ POS ไม่รู้จัก ให้ปฏิเสธการเชื่อมต่อพร้อมเหตุผล
  - โครงหน้าตั้งค่า: หัวข้อ "การเชื่อมต่อ" ของ admin หลัง login — ส่วนบนเว้นไว้ให้เซิร์ฟเวอร์ร้านของ ticket 29b ส่วนล่างเป็น ERP
  - เก็บ credential อย่างปลอดภัย: ไม่ log, ไม่ส่งกลับไปที่แอปหลังบันทึก, และห้ามอยู่ในไฟล์ export ใดๆ
  - ออกจากโหมดเชื่อมต่อได้ ข้อมูลที่ mirror ไว้ยังอยู่และกลับมาแก้ได้ บันทึกพฤติกรรมนี้ใน DECISIONS
- **ดึง master data ตามเวอร์ชัน** ตามสัญญา v1: `GET /api/v1/master-data/changes?since=N&limit=` ดึงเป็นรอบ และมีปุ่ม
  "ดึงทันที" เก็บเวอร์ชันล่าสุดที่นำไปใช้แล้ว ดึงต่อจนกว่า `hasMore` เป็น false ถ้าเน็ตหลุดนานก็ดึงต่อจากเวอร์ชันนั้นได้โดยไม่พลาด
  - `data` คือทั้งระเบียน ให้**เขียนทับ ห้าม merge** และข้าม `entityType` หรือฟิลด์ที่ไม่รู้จัก (1.x เพิ่มได้อย่างเดียว)
  - **รายการสินค้าใน ERP → วัตถุดิบใน POS** จับคู่ด้วย item code หน่วยของวัตถุดิบ mirror = `baseUnitCode` ของ ERP
    (`kg`, `piece`, `l`…) แสดงเป็นชื่อหน่วยตามภาษาของแอป แทนหน่วยข้อความอิสระของโหมดเดี่ยว ส่วน `purchaseUnits` เก็บไว้ได้แต่
    POS ยังไม่ใช้ รหัสหน่วยที่แอปไม่รู้จักให้แสดงรหัสตรงๆ ห้ามเดา
  - **สาขาใน ERP → สาขาใน POS** จับคู่ด้วย**รหัสสถานที่กลาง** (`^[A-Z0-9][A-Z0-9-]{1,31}$`) รหัสสาขาที่ไม่ตรงรูปแบบใช้ใน
    โหมดเดี่ยวต่อได้ แต่ต้องแก้ก่อนเข้าโหมดเชื่อมต่อ โดยหน้าจอต้องบอกว่าสาขาไหนต้องแก้อะไร
  - ถ้า ERP แทนสถานที่ด้วยรหัสใหม่ (*superseded by* — รหัสที่ใช้งานแล้วแก้ไม่ได้ ต้องสร้างใหม่แทน) POS ย้ายสาขานั้นไปใช้
    รหัสใหม่ตามลิงก์ โดยประวัติการขายเดิมไม่หาย
- **ในโหมดเชื่อมต่อ หน้าจัดการสิ่งที่ ERP เป็นเจ้าของเป็นอ่านอย่างเดียว** และมีป้าย "จัดการใน PaynEat ERP" ส่วน API
  ปฏิเสธการแก้ด้วย 409 พร้อมเหตุผล (ใน ticket นี้คือวัตถุดิบและสาขา — เมนู ราคา สูตร อยู่ใน ticket 27)
- **สต๊อกช่วงคั่น (สำคัญ)**: ในโหมดเชื่อมต่อ ยอดคงเหลือของสาขาเป็นของ ERP (ERP ADR-0003) แต่สัญญา v1 ยังไม่มี feed
  ยอดคงเหลือกลับมาที่ POS ดังนั้นระหว่างนี้:
  - POS **ต้องไม่ใช้ยอดวัตถุดิบในเครื่องเป็นความจริง**: ปิดการปิดขายอัตโนมัติจากสต๊อกในเครื่อง และใช้การปิดขายด้วยมือแทน
  - **การขายต้องไม่ถูกบล็อกเพราะสต๊อก**
- **telemetry** (สัญญา v1.2 หัวข้อ "POS↔ERP integration lines"): log การดึง master data มี `event`, จำนวนรายการ และเวอร์ชัน
  ส่วน credential ห้ามโผล่ **ทุกบรรทัดเรื่องการดึง รวมที่ล้มเหลว** (เน็ตหลุด, 401, 5xx) มี `pos_instance` ห้ามเดาค่าที่ไม่รู้
- **contract test**: ตรวจ response ของ ERP ตัวอย่างกับไฟล์สัญญา POS v1 ใน CI โดยปักเวอร์ชัน 1.0.0
- **Demo Mode**: แสดงสถานะ "ใช้งานเดี่ยว" เสมอ

## ขอบเขตที่ตั้งใจไม่ทำ
- ดึงเมนู ราคา สูตร จาก ERP — ทำใน `27-erp-menu-pull.md` (สัญญา v1.1 จาก PaynEat-ERP#16)
- feed ยอดคงเหลือสาขาจาก ERP เพื่อขึ้นป้าย "หมด" อัตโนมัติ — รอสัญญารุ่นถัดไปเช่นกัน
- single sign-on ระหว่าง POS กับ ERP
- การส่งยอดขาย (ticket 26)

- **backend** — `backend/src/modules/erp/` (client, contract, repository, service, routes) และ migration 0002
  (`erp_connection`, `erp_instance_branches`, `erp_items`, `erp_locations`, `ingredients.item_code`)
  - `PUT/GET/DELETE /api/v1/erp/connection` (admin), `POST /api/v1/erp/pull` (admin), `GET /api/v1/erp/mode` (ทุกบทบาท)

- **แอป** — หัวข้อ "การเชื่อมต่อ" ในหน้าตั้งค่า (admin): ส่วนบนเซิร์ฟเวอร์ร้าน (สำหรับ 29b) ส่วนล่าง PaynEat ERP พร้อมรายการสาขาที่
  ต้องแก้รหัสและปุ่มแก้ หน้าวัตถุดิบเป็นอ่านอย่างเดียวพร้อมป้าย "จัดการใน PaynEat ERP" ชื่อหน่วยจาก ERP แสดงตามภาษา
  ฟอร์มวัตถุดิบมีช่องรหัสสินค้า (ตั้งไว้ก่อนเชื่อมต่อได้) โหมดสาธิตขึ้น "ใช้งานเดี่ยว" เสมอ
