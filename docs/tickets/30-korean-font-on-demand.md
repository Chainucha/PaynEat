# Ticket: โหลดฟอนต์เกาหลีเฉพาะเมื่อต้องใช้ — ไม่ให้ทุกคนที่เปิดเว็บต้องโหลด 3.2MB ที่ไม่ได้ใช้

**Priority:** 🟡 Medium — ความเร็วเปิดเดโมบนเว็บ
**สถานะ (2026-09-27):** ⏳ ยังไม่เริ่ม — เริ่มได้
**Ref:** `docs/DECISIONS.md` #64, #74 (ฟอนต์เกาหลีครบ KS X 1001), PR #33
**Blocked by:** ไม่มี

## ปัญหา
#74 ขยาย NotoSansKR เป็น 2,350 พยางค์ครบทุกน้ำหนัก ไฟล์รวมโตจากราว 256KB เป็นราว 3.2MB และประกาศไว้ใน `fonts:` ของ
`app/pubspec.yaml` คู่กับ NotoSansThai ถ้า Flutter บนเว็บโหลดฟอนต์ทุกตัวที่ประกาศไว้ตั้งแต่เปิดหน้า คนไทยที่เปิดเดโมบนมือถือจะโหลด
ฟอนต์เกาหลีไปโดยไม่ได้ใช้เลย ส่วนร้านที่ใช้ผ่าน LAN ไม่ค่อยรู้สึก แต่เดโมสาธารณะคือหน้าแรกที่คนเจอ

## ขอบเขตงาน
- **วัดก่อน**: build เว็บจาก `main` แล้วเปิดใน Chromium (โหมดไทย) บันทึกว่าไฟล์ `NotoSansKR-*.ttf` ถูกโหลดตอนเปิดหน้าจริงหรือไม่
  และจำนวนไบต์ที่โหลดก่อนหน้าแรกพร้อมใช้ **ถ้าไม่ได้ถูกโหลดตั้งแต่ต้น ให้ปิด ticket นี้พร้อมผลวัด** ไม่ต้องแก้อะไร
- ถ้าถูกโหลดจริง: เอา NotoSansKR ออกจาก `fonts:` แล้วโหลดตอนใช้งานด้วย `FontLoader` จาก asset เดิม
  - โหลดเมื่อผู้ใช้เลือกภาษาเกาหลี (รวมตอนเปิดแอปที่จำภาษาเกาหลีไว้)
  - **ตัวอักษรเกาหลีต้องไม่เป็นกล่องสี่เหลี่ยมในทุกภาษา** — ข้อมูลที่กรอกเป็นเกาหลีจะโผล่ในหน้าจอภาษาไทย/อังกฤษได้ (#74)
    เช่น ชื่อลูกค้า dev เสนอวิธีตรวจว่ามีอักษรเกาหลีในข้อมูลที่กำลังแสดงแล้วโหลดฟอนต์ตามนั้น หรือเหตุผลว่าทำไมฟอนต์สำรองของ
    แพลตฟอร์มพอ **ต้องใช้ได้ในร้านที่ไม่มีอินเทอร์เน็ต** — ห้ามพึ่งการดึงฟอนต์สำรองจาก Google Fonts ผ่านเน็ต
  - ระหว่างโหลดอนุญาตให้ข้อความเกาหลีแสดงด้วยฟอนต์สำรองชั่วคราว แต่ต้องไม่กระพริบทั้งหน้าหรือเสียตำแหน่งที่กำลังพิมพ์
- Android/iOS: ฟอนต์ยังอยู่ในแอปเหมือนเดิมได้ (ไม่มีค่าโหลดผ่านเน็ต) ใช้กลไกเดียวกันเพื่อให้โค้ดทางเดียว
- `korean_font_coverage_test.dart` ยังต้องผ่าน (ตรวจตัวไฟล์ ไม่ขึ้นกับวิธีโหลด)

## ขอบเขตที่ตั้งใจไม่ทำ
- ตัดฟอนต์ไทยให้เล็กลง — ภาษาหลัก ต้องมีตั้งแต่แรก
- แบ่งฟอนต์เกาหลีเป็นหลายไฟล์ตามช่วงอักษร (unicode-range) — ซับซ้อนเกินผลที่ได้ในรอบนี้
