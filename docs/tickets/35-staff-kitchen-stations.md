## ปัญหา
ticket 34 ให้จอครัวจำสถานีที่เลือกไว้ "ต่อเครื่อง" ซึ่งพอสำหรับแท็บเล็ตที่ติดอยู่กับที่ แต่ร้านที่พนักงาน
หยิบแท็บเล็ตเครื่องไหนก็ได้ หรือเปิดจอครัวบนเบราว์เซอร์ใหม่ทุกกะ ต้องมาแตะเลือกสถานีใหม่ทุกครั้ง
ทั้งที่รู้อยู่แล้วว่าคนนี้ทำบาร์ และ `docs/DECISIONS.md` #94 เขียนไว้ว่า "ไม่ทำ" การผูกสถานีกับบัญชี
เพราะตอนนั้นประเมินว่าสถานีเป็นเรื่องของเครื่องล้วน ๆ — เจ้าของโปรเจกต์ขอให้เพิ่มเข้ามา

## ขอบเขตงาน

### 1. ตารางเชื่อม `user_stations`
- migration `0007_user_stations` — รูปเดียวกับ `user_branches` ทุกจุด (`PRIMARY KEY (user_id, station_id)`,
  `ON DELETE CASCADE` ทั้งสองทาง, index บน `station_id`)
- **ผูกได้หลายสถานีต่อคน** เพราะคนทำครัวร้อนที่ช่วยดูเตาย่างด้วยไม่ควรต้องมีสองบัญชี
- ไม่มีแถว = ไม่ผูกสถานี = พฤติกรรมเดิมก่อน ticket นี้ (เห็นทุกสถานี) — บัญชีที่มีอยู่แล้วทุกบัญชีจึงไม่เปลี่ยน

### 2. API
- `POST /users` และ `PATCH /users/:id` รับ `stationIds` (ชุดเต็มเสมอ ไม่ใช่ส่วนเพิ่ม): `[]` = ถอดออกทั้งหมด,
  ไม่ส่งมา = ไม่แตะ — หลักเดียวกับช่องที่ล้างค่าได้ช่องอื่น
- DTO ของผู้ใช้เปิดออกสองรูป: `stationIds` ให้หน้าจัดการพนักงานติ๊กช่อง และ `stationCodes` ให้จอครัว
  ใช้เลือกชิป (ชิปทำงานด้วยรหัสสถานี)
- `POST /auth/login`, `POST /auth/select-branch` และ `GET /auth/me` พก `stationCodes` มาด้วย
  **ไม่ใส่ใน JWT** เพราะเปลี่ยนได้ตลอดและไม่ได้ใช้ตัดสินสิทธิ์
- `stationIds` ที่ไม่มีจริง → 400 (ใช้ `kitchenStationService.assertStationExists` ตัวเดียวกับเมนู/หมวดหมู่)
- สิทธิ์ไม่เปลี่ยน: ยังเป็นขอบเขตของ T22 (#92) ทุกข้อ ผู้จัดการตั้งสถานีได้เฉพาะพนักงานระดับต่ำกว่าในสาขาของตัวเอง

### 3. จอครัว
- ยังไม่เคยเลือกสถานีบนเครื่องนี้ → เปิดมาที่สถานีแรกที่ผูกกับบัญชี
- **ไม่ล็อก** — ชิปยังแตะได้ทุกสถานี และเมื่อแตะแล้วค่าของเครื่องจะทับค่าของบัญชีตั้งแต่นั้นไป
  (รวมถึงตอนเลือก "ทุกสถานี" ซึ่งถูกเก็บเป็นค่าของเครื่องเหมือนกัน)
- ไม่ซ่อนตั๋วจากใครเลย: บัญชีที่ถูกตั้งสถานีผิดจึงไม่มีทางทำให้ตั๋วหายไปเงียบ ๆ

### 4. หน้าจัดการพนักงาน
- ฟอร์มเพิ่มพนักงานมีช่องติ๊กสถานี แสดงเฉพาะบทบาทที่เห็นจอครัว (`admin`/`manager`/`kitchen`/`waiter`)
- เมนู ⋮ ของแต่ละแถวมี **"ตั้งสถานีครัว"** เปิดกล่องติ๊กสถานีของคนนั้น
- ไม่มีสถานีในระบบ (หรือดึงไม่สำเร็จ) → ไม่แสดงช่องนี้เลย หน้าจัดการพนักงานทำงานได้เหมือนเดิมทุกอย่าง

### 5. โหมดสาธิต
มิเรอร์ครบ: แถว user เก็บ `stationIds`, DTO เปิด `stationIds` + `stationCodes`, สร้าง/แก้ผ่านเส้นทางเดิม

## ขอบเขตที่ตั้งใจไม่ทำ
- **บังคับว่าเห็นได้แค่สถานีของตัวเอง** — เลือกแบบ "เลือกให้ล่วงหน้า" ไม่ใช่ "ล็อก" เพื่อไม่ให้บัญชีที่ตั้งผิด
  ทำให้ตั๋วหาย ถ้าจะบังคับต้องกรองที่ backend ด้วย ไม่ใช่แค่ซ่อนในแอป (เป็นงานแยกถ้าจะเอาจริง)
- **ใส่ `stationIds` ใน JWT** — จะทำให้การแก้สถานีไม่มีผลจนกว่า token หมดอายุ
- **ผูกสถานีต่อสาขา** — สถานีเป็นข้อมูลระดับเครือร้าน (ดู #94) การผูกพนักงานจึงเป็นระดับเครือเช่นกัน
- **เลือกสถานีตอน login เหมือนเลือกสาขา** — หน้าจอเพิ่มอีกชั้นโดยไม่จำเป็น ชิปบนจอครัวทำหน้าที่นี้อยู่แล้ว

## Acceptance Criteria
- [x] `POST /users` ด้วย `stationIds: [bar]` → บัญชีใหม่มี `stationIds`/`stationCodes` ตรงตามที่ส่ง
- [x] `PATCH /users/:id` ด้วยสองสถานี → ได้ทั้งสอง เรียงตาม `sort_order` ของสถานี
- [x] `PATCH` ด้วย `stationIds: []` → ถอดออกทั้งหมด; ไม่ส่ง `stationIds` → ค่าเดิมไม่ถูกแตะ
- [x] `stationIds` ที่ไม่มีจริง → 400
- [x] `POST /auth/login` และ `GET /auth/me` ของบัญชีที่ผูกไว้ → พก `stationCodes` มาด้วย
- [x] บัญชีที่ไม่ได้ผูก (ทุกบัญชีเดิม) → `stationCodes: []` และจอครัวเห็นทุกสถานีเหมือนเดิม
- [x] จอครัว: บัญชีผูก `bar` และเครื่องนี้ยังไม่เคยเลือก → เปิดมาที่ชิป บาร์ โดยไม่เขียนค่าลงเครื่อง
- [x] จอครัว: เครื่องเคยเลือกไว้ (รวม "ทุกสถานี") → ค่าของเครื่องชนะค่าของบัญชี
- [x] หน้าจัดการพนักงาน: ช่องติ๊กขึ้นเฉพาะบทบาทที่เห็นจอครัว และเมนู ⋮ มี "ตั้งสถานีครัว"
- [x] ขอบเขตผู้จัดการตาม T22 (#92) ไม่เปลี่ยน
- [x] README ไทย/อังกฤษ/เกาหลี, `docs/DECISIONS.md` #95, `docs/FEATURE-GAP-ANALYSIS.md` และ
      `backend/docs/openapi.yaml` อัปเดตตาม `CLAUDE.md`
