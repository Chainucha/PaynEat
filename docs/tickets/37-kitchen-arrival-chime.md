# Ticket: เสียงเตือนเมื่อตั๋วเข้าจอครัว

**Priority:** 🟠 High — จอครัวเงียบสนิท ตั๋วใหม่โผล่มาโดยไม่มีเสียง คนครัวที่ก้มหน้าทำอาหารอยู่ไม่เห็น
**สถานะ (2026-10-09):** ✅ เสร็จ — การตัดสินใจอยู่ที่ `docs/DECISIONS.md` #103 (ข้อที่ตรวจในเบราว์เซอร์จริงยังรอก่อน merge)
**Ref:** `docs/DECISIONS.md` #97 (ชิปสถานีจำต่อเครื่อง), #98 (สถานีของบัญชีเป็นค่าตั้งต้น), #8 (โหมดสาธิต)
**Blocked by:** ไม่มี · ทำคู่กับ ticket 36 ได้

## ปัญหา
`KitchenController` ฟัง `kitchen:ticket` / `order_item:updated` / `order:updated` แล้วโหลดคิวใหม่เงียบ ๆ
และ poll สำรองตอน socket หลุด แต่ทั้งแอปไม่มีเสียงหรือการแจ้งเตือนเลยสักจุด ตั๋วใหม่จึงพลาดได้ง่าย

## คำศัพท์ (ดู `CONTEXT.md`)
**ตั๋วเข้า (ticket arrival)** = รายการใหม่เข้าคิว pending ของสถานี ไม่ว่าจากออเดอร์ใหม่ สั่งเพิ่มเข้าออเดอร์เดิม
หรือ QR — การเปลี่ยนสถานะและการยกเลิกไม่นับ

## ขอบเขตงาน (แอปอย่างเดียว ไม่แตะ backend)

### 1. ตรวจจับตั๋วเข้าในเครื่อง
- เทียบรายการระหว่างการโหลดคิวแต่ละรอบ: id ของรายการ `pending` ที่ **ไม่เคยเห็น** ใน session นี้และผ่านตัวกรอง
  สถานีที่เลือกอยู่ (`visibleQueue`) = ตั๋วเข้า
- ใช้ diff ในเครื่อง ไม่ใช่ event จาก server — จึงดังได้แม้ตอน socket หลุดและข้อมูลมาจาก polling สำรอง
  (ตั๋วพลาดเงียบ ๆ ตอนเน็ตสะดุดคือปัญหาที่ ticket นี้มาแก้)
- รายการที่ถูกเลิกทำถอยกลับมาเป็น pending ไม่นับ เพราะ id เคยเห็นแล้ว

### 2. เมื่อไหร่ **ไม่** ดัง
- โหลดครั้งแรกตอนเปิดจอ และตอนสลับชิปสถานี → แค่ตั้ง baseline ใหม่ ไม่ดัง
- ตั๋วเข้าหลายใบติดกัน หรือ backlog หลังต่อเน็ตกลับมา → ดัง **ครั้งเดียว** (debounce ไม่กี่วินาที)
- ปิดเสียงไว้ → ไม่ดัง แต่ยังไฮไลต์การ์ด
- ชิป "ทุกสถานี" → ดังเมื่อมีตั๋วเข้าสถานีใดก็ได้

### 3. ไฮไลต์การ์ด
- การ์ดของตั๋วเข้ามีป้าย "ใหม่" / ขอบเรืองแสง จนกว่าจะถูกแตะครั้งแรก หรือสถานะเปลี่ยน หรือครบ 2 นาที
- ไม่เพิ่มความสูงการ์ด — กว้าง 360px ต้องไม่ล้น

### 4. เสียง
- เสียงสั้นเสียงเดียวที่รวมมากับแอป ลิขสิทธิ์สะอาด (สร้างเองจากสคริปต์หรือ CC0 — ถ้าเป็นของบุคคลที่สามให้ลง `NOTICE`)
- เว็บ: เบราว์เซอร์บล็อกเสียงจนกว่าผู้ใช้จะแตะหน้าจอครั้งแรก → จอครัวแสดงปุ่ม/แถบ "แตะเพื่อเปิดเสียง" ครั้งเดียว
  จนกว่าจะปลดล็อก (ต้องไม่ขวางการใช้งานจอ)
- Android: เล่นได้ทันที
- **เลือก package ตอนวางแผน**: เว็บเล่นผ่าน `package:web` (`HTMLAudioElement`) ที่มีอยู่แล้วได้โดยไม่เพิ่ม dependency
  แต่ Android ต้องใช้ package เสียง (เช่น `audioplayers`) — ตรวจ license, ขนาด build, และเพดานเวอร์ชัน Flutter (#111)
  ก่อนเพิ่ม และซ่อนไว้หลัง interface เดียวเพื่อให้เทสต์ใช้ตัวปลอมได้

### 5. ปิดเสียง
- สวิตช์ลำโพงบนหัวจอครัว จำ **ต่อเครื่อง** (`StorageKeys`) ไม่ถูกล้างตอน logout — เหมือนชิปสถานี (#97)

### 6. โหมดสาธิต
ไม่ต้องมีโค้ดเฉพาะโหมดสาธิต — การตรวจจับเทียบจากคิวที่โหลดมา ไม่ผูกกับแหล่งข้อมูล จึงทำงานเหมือนกันทั้งสองโหมด
แต่โหมดสาธิตเป็นเครื่องเดียว ไม่มีเครื่องอื่นส่งตั๋วเข้ามาระหว่างที่จอครัวเปิดอยู่ จึงแทบไม่มีโอกาสได้ยินเสียงในโหมดนี้ (#8)

## ขอบเขตที่ตั้งใจไม่ทำ
- **Push notification ของระบบ/เบราว์เซอร์ตอนแอปอยู่เบื้องหลังหรือจอดับ** — ต้องใช้ service worker และขอสิทธิ์
  จอครัวปกติเปิดค้างไว้หน้าเดียวอยู่แล้ว
- **แจ้งพนักงานเสิร์ฟ/แคชเชียร์ว่า "ออเดอร์ถึงครัวแล้ว"** — ticket นี้เฉพาะจอครัว
- **การสั่น**, **เลือกเสียงได้หลายแบบ**, **ดังซ้ำจนกว่าจะรับ** — ไว้ทีหลังถ้าร้านขอ
